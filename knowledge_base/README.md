# Knowledge base export

A complete, portable snapshot of the political knowledge graph: every node, relationship, verified claim,
source, and the Exa research outputs behind them. It's generated by `make export` (`python -m polgraph export`).
See `manifest.json` for the export time, counts, Exa spend, and a SHA-256 checksum of every file.

## Contents

| Path | What it holds |
| --- | --- |
| `graph/nodes.jsonl` | One JSON object per node: `id`, `label`, and all properties (sorted by id). Labels: Earth, Continent, Country, DemocracyAssessment, ContactRule, GovernmentLevel, GovernmentBody, PoliticalOffice, Person, PoliticalParty, Term, Source. |
| `graph/edges.jsonl` | One JSON object per relationship: `src`, `type`, `dst`, and its properties (e.g. `HOLDS_OFFICE` carries `current`, `start`, `end`, `evidence_status`, `confidence`, `constituency_code`, `seat_type`; `SUPPORTED_BY` carries the supporting `snippet`). |
| `bundles/<ISO2>/` | System B input bundles, one JSON file per politician (`person__<ISO2>__<slug>.json`) plus `index.json`: the Country node, the Person node, the subgraph between them (GovernmentLevel → GovernmentBody → PoliticalOffice → Term) and the party/source leaves, with a content `sha256`. Derived from `graph/*.jsonl` by `make export-bundles`; re-run it after every export. |
| `tables/countries.csv` | All 249 countries: ISO codes, continent, `regime_group` (Democratic / Partly democratic / Authoritarian / Unclassified), detailed class, each index's rating, whether the indices agree, whether the government structure has been researched. |
| `tables/officeholders.csv` | Every office-holding, flattened: country, hierarchy path, office, how it is filled, seat type, constituency, person, party, dates, evidence status, confidence, and the source URLs. |
| `research/agent_runs/*.json` | Each Exa Agent run: the query sent, the run id, cost, the schema-validated structured output, and field-level citations (`grounding`). This is the raw research before our verification. |
| `research/unresolved_claims.jsonl` | Claims that were rejected (no fetched page supported them) or stored with weaker corroboration, with the reason and the URLs checked. |
| `research/pipeline_runs.json`, `stage_runs.json` | Every build: when it ran, its mode, per-stage results and coverage. |
| `research/reviews.json` | Human review decisions for the eligibility checks (empty so far). |
| `research/exa_usage_ledger.csv` | Every Exa call: endpoint, purpose, cost, and whether it came from cache. |

## Loading it

```bash
make import-kb          # or: cd backend && python -m polgraph import --from ../knowledge_base
```

Imports go into whichever backend `.env` selects (`GRAPH_BACKEND=neo4j` or `sqlite`). They are idempotent upserts,
so importing twice, or into a graph that already has data, does not create duplicates. No Exa key is needed to
import or browse.

Without the app, the files are readable on their own: the CSVs open in any spreadsheet, and the JSONL loads with
one line of pandas (`pd.read_json("graph/nodes.jsonl", lines=True)`).

## Not included

* **Raw page text** from the Exa response cache: full third-party articles and documents (copyrighted, ~13 MB).
  The graph keeps each source's URL, title, domain and the short supporting snippet instead.
* Monitor webhook secrets and any API keys or credentials.
